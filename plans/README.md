- 002 and 003 depend on 001 because the baseline tests and checks must exist
  before security, lifecycle, and packaging changes can be trusted.
- 004 depends on 001 because settings loading and activity-detail layout need
  regression coverage before performance/UI changes are considered release
  safe.
- 005 depends on 004 because it refines the settings UI and its provider-loading
  state introduced there.
- A release candidate must also have a clean `git status`, a reviewed commit
  containing the current feature work, and no credential files in the release
  tree.

## Findings considered and rejected

- A broad performance rewrite is not worth doing before the first release:
  the app is a local single-user desktop tool and no measured hot path was
  established.
- Replacing all broad exception handlers is deferred until the release gate
  exists; doing it without characterization tests risks breaking the GUI's
  best-effort integrations.
